## Workflow (adapted from sdlc-harness)
- `/game-plan` → user approves → `/clear` → `/game-cook <plan-dir>` (ends with `/game-review`) → `/game-ship [<plan-dir>]` (branch, commit, PR, squash-merge; user-invoked only). Side tools: `/game-research`, `/game-redteam`.
- Plans live in `plans/<YYMMDD-HHMM>-<slug>/` (has `.gdignore`); manage with `python tools/dev/plan.py new|approve|status|list`. Approval is content-hashed — editing an approved plan = DRIFT, re-approve.
- Token budget is a hard constraint (per user): skills run in the main thread by default; subagents only via explicit flags (`/game-plan --hard`, `/game-cook --subagents|--test-agent|--review-agent`). All agents run sonnet/medium.
- Verification gate: `python tools/dev/check.py [--all] [--shots <dir>]` (import + per-file parse + 120-frame headless run + optional day/sunset/night screenshots). Known accepted warnings: `tools/dev/known_issues.txt`.
- Evidence rules: `.claude/workflow/evidence.md`; review/red-team checklist: `.claude/workflow/godot-checklist.md`. Subagents: `planner`, `researcher`, `red-teamer`, `developer` (cook phase > 8 files), `tester`, `code-reviewer`. Plan interview rules: `.claude/skills/game-plan/references/interview.md`.
- Temporary engine probes go in `res://_probes/` (gitignored), run with `--headless --path . --script`, delete after.

## Rules
- Fully typed GDScript (`untyped_declaration` warning is on). Autoloads have no `class_name`.
- Feature-based folders under `src/`; raw art/audio under `assets/`.
- Cross-system communication via `EventBus`; story progress via `GameState` flags.
- Jolt: physics bodies must use uniform scale.
- Do not store generated MultiMesh data in .tscn (GrassField clears it on save).
- Pixel art is generated by `python tools/art/gen_terrain.py` (PIL); map layout = small RGBA PNG (R dirt, G tall grass, B water, A=0 forest) read by TerrainGround/TerrainWater/TerrainCollision/GrassField; its .import must keep fix_alpha_border=false.
- Player sprite: `python tools/art/gen_character.py` → heroine_sheet.png + heroine_frames.tres (anims `<idle|walk|attack|dodge|hurt>_<down|up|side>`; Player picks the suffix from facing vs camera; left = flip of side).
- Current focus (per user): graphics & lighting first; no enemies yet.
- Performance is mandatory (per user): follow `docs/PERFORMANCE_ROADMAP.md` — budgets, milestone order, and the per-feature checklist (§4). Measure before/after any rendering/gameplay change with `tools/bench/run_bench.py` (a `[ĐỎ]` vs baseline is a signal; conclude from a same-session A/B); every feature needs a Low-tier behavior.
- Bake-first (per user): no per-pixel procedural noise/loops in shaders, no runtime mesh building when it can be baked by `tools/`. Lighting is fixed per area → static light/shadow via LightmapGI (roadmap Mốc 1B).
